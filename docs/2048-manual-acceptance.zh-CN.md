# Super-Org 人工验收 · 2048 项目

用测试群和测试仓库跑一遍「讨论 → 分工 → 执行 → 交付 → 验收 → 下一项」。已有测试项目可以继续使用。开始前记录本轮项目、任务、工单和验收版本，便于区分历史结果。

首次操作可以先按[2048 图文教程](tutorials/2048.zh-CN.md)建立项目并执行到交付。

## 准备

- [ ] 启动完整服务。工作台的「Agent 状态」显示执行可用，钉钉 Stream 已连接。
- [ ] 将测试群配置为首次纪要入口，由实际参与者 @ 机器人发送「登记项目成员」。把相应成员加入项目，或在首次纪要中指派已登记成员。
- [ ] 若验证 GitHub，准备可读写的测试仓库和可创建 PR 的基线。配置 GitHub 来源、事件类别和评论作者的来源授权。 [部署与运维](deployment.zh-CN.md)
- [ ] 若验证自动开工，先在测试项目开启「自动推进」。测试时保存机器人实际回执、工作台截图或仓库链接。

## 提交首次会议纪要

使用实际名册姓名替换括号内的分工，由参与者在群里 @ 机器人提交：

```text
项目会议纪要
项目名称：2048 游戏开发验收

目标：交付可在浏览器运行的 2048 MVP，支持键盘和触屏操作。
A：整理移动、合并、计分和重新开始的规则与测试清单。由 Agent 执行，[成员甲] 验收。
B：按 A 的清单实现游戏并提供可复现的测试结果。由 Agent 执行，[成员乙] 验收。依赖 A 验收通过。
C：在浏览器做一轮人工试玩并记录问题。[成员丙] 执行。依赖 B 验收通过。
验收重点：每个方块一轮只能合并一次、有有效移动才生成新块、重新开始清空本局分数。
```

- [ ] 核对目标、三项任务、分工、依赖与验收条件。项目待开工，任务没有提前派发。
- [ ] 引用 B 并补充一项可检查的验收条件。看板只修改对应任务。
- [ ] 验证先不关联仓库也能维护项目与任务。之后为 GitHub 测试绑定仓库，引用 B 请机器人新建 Issue，核对远端链接回填到 B。

## 从开工到后续推进

| 操作 | 预期结果 |
| --- | --- |
| 在群里确认开工并请 Agent 完成 A | A 进行中，生成一个工单。任务详情显示实际执行阶段 |
| A 报告交付 | 生成一个待验收版本，通知 A 的负责人，附带证据与操作提示 |
| 负责人对本版提出具体退回意见 | 记录退回原因。继续交付后产生新版，旧版引用无法通过新版 |
| A 的当前版验收通过 | A 完成。若开启自动推进，B 的依赖解除，`task.ready` 唤起 Agent，符合条件时只登记一次 B 工单 |
| B 在执行中遇到阻塞 | `task.blocked` 记录问题并通知项目群。在原任务补充要求，检查继续同一工单 |
| 请 Agent 在两分钟后再检查 B，若无变化保持安静 | 登记一次检查，`check.due` 到期后唤起 Agent。无变化时不重复发消息 |
| 运行 B 的实际产物，并由负责人验收 | 检查可操作界面、合并、计分、重开及关键异常路径。通过后 B 完成，具备后续条件的 C 可推进 |
| 提交 C 的人工试玩记录并验收 | C 有独立交付证据与验收记录，无须 Agent 工单 |

开工和验收都可在网页操作。用不同入口交叉核对同一任务及同一交付版本。阻塞细节、当前工单及下一次预约分别从任务详情和「推进记录」查看。

## PR 评论、代码交付与 Issue 同步

在 B 开工前将交付方式设为 PR，明确目标分支，把 Issue 标为「负责解决」。此测试需要一个真实、已绑定 B 的 PR。

- [ ] 用获授权的真人账号发一条只读问题，再发一条明确修改请求。观察普通评论、行评论和 Review 在推进记录中归入当前 PR 和任务。只读问题可以直接答复，修改交给原工单。
- [ ] 在行讨论核对文件、行、提交和原线程。Worker 正常报告测试或提出阻塞问题后，原线程收到真实结果。重复轮询或机器人自己的回复不应引发新一轮处理。
- [ ] 提交新版代码后核对旧提交证据。GitHub Approve 或 Request changes 属于技术评审，任务业务验收仍依赖成员对当前交付的决定。
- [ ] 由有权限的成员合并 PR。成功报告和当前 PR 合并证据齐备后，项目只请求一次人工验收。
- [ ] 人工通过本版后查看远端 Issue 与同步回执。标为「负责解决」的 Issue 应关闭，标为「仅参考」的保持独立。若权限失败，在推进记录核对原因，修好权限后重试原同步动作。

每一项记录操作入口、触发事件、Agent 的实际工具结果、工单 ID 和真实回执。记录群消息是否在用户客户端显示，区分平台接受与已读。自动测试环境和最近实测范围见[验证记录](events/acceptance.zh-CN.md)。
