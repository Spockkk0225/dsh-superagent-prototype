## 1. 第一次会议：可直接贴进群里的草稿

下面是待团队确认的测试纪要，不是真实开会的事实。确认分工后，由已登记成员 @ 机器人并粘贴。名字应与目录一致；如果实际分工不同，先修改草稿。

```text
项目会议纪要
项目名称：2048 游戏开发验收
GitHub 仓库：longbinlai/super-agent-2048

参会：Robin、李顺阳、楼昀恺。

项目目标：做一个可在本机浏览器实际游玩的 2048 网页游戏，使用原生 HTML、CSS、JavaScript。先完成单人离线 MVP，不做登录、排行榜、撤销和联网功能。

已确定的首版规则：
1. 棋盘为 4×4，初始随机出现两个数字；生成数字为 2 或 4，概率分别为 90% 和 10%。
2. 支持方向键及可点击的四个方向按钮；相同数字按移动方向合并，同一次移动中每个格子至多参与一次合并。
3. 分数增加值等于本次新合成数字之和。只有棋盘实际变化时才生成一个新数字；无效移动不加分、不生成数字。
4. 达成 2048 时显示胜利并允许选择继续；没有空位且不能合并时显示结束。
5. 重新开始清空分数，重新生成初始棋盘。界面在电脑和手机宽度下可用。

本次确认三项行动：

A. 整理 2048 规则与测试清单。
由 Agent 执行，Robin 负责验收，不依赖其他任务。
交付直接包含在工单结果里，不要求修改仓库文件。
验收条件：覆盖上述规则，给出移动前棋盘、操作、预期棋盘和分数变化；至少覆盖 [2,2,2,2] 向左合并为 [4,4,0,0]、单次移动禁止再次合并、无效移动不生成数字、胜负判定及重开。

B. 实现 2048 游戏 MVP。
由 Agent 编写代码，李顺阳负责验收，依赖 A 验收通过。
交付包括完整网页、纯规则逻辑测试、README 启动说明。测试使用 node --test；网页可由本机静态 HTTP 服务打开，不依赖外部 CDN。
验收条件：规则与 A 一致；按键和按钮均可玩；计分、胜负、重开正确；小屏布局可用；测试通过。报告给出实际交付目录、启动命令、测试结果、变更文件和提交信息。满足 PR 条件时另给出 PR 链接，由人审查合并。

C. 人工试玩并整理首版验收结果。
由楼昀恺人工执行并确认该任务结果，依赖 B 验收通过。
验收条件：实际试玩移动、合并、计分、无效移动和重开，检查窄屏布局；提交实际步骤、观察结果和问题清单，不能只写“已测试”。

本次只建立项目、目标、任务和分工。保持待开工，关闭自动推进，不派发任何工单。
任务均可暂不关联 Issue，后续由成员决定哪项需要。
```

通过标准：

- [ ] 先收到接收信号，随后收到真实规划结果；不能把“正在整理”当作建项完成。
- [ ] 项目页出现且只有一个新项目；状态待开工，自动推进关闭，执行工单数为 0。
- [ ] 三项任务的执行方式、具体条件和依赖正确：A → B → C。
- [ ] A 的负责人为 Robin，B 为李顺阳，C 为楼昀恺。Agent 任务的负责人承担该任务的验收；这是任务分工，不是永久成员角色。
- [ ] 成员来自保留的目录，没有因重演重复建人；仓库保存在该项目里，Issue 字段允许为空。
- [ ] 刷新页面后仍可找到该项目。如果机器人提问，记录其具体缺项；只有确有缺项才补充，不为推进而反复发“更新计划”。

| X1 双端冲突 | 对同一待验收版本，看板提交通过，同时负责人在群里引用它提出退回 | 只有一个有效决定；另一项提示已失效；没有双份推进或新版被误处理 |
| X2 验收范围更新 | 打开某版验收窗口，再调整验收条件或负责人，然后提交旧窗口 | 旧请求失效，保留历史；不能套用到新条件或新负责人 |
| X3 重启恢复 | 在待验收状态按相同配置重启服务 | 当前版本、证据和记录保留；不重复群通知、建 Issue 或派工 |
| X4 无仓库项目 | 另轮测试时归档本轮并解除群绑定，首次纪要省略 GitHub 仓库行，创建只需分析报告的任务 | repository 为空，仍可管理、派工报告和验收；不默认套用 2048 仓库 |
| X5 PR 扩展 | 有 main 基线后，检查 B 的真实分支、提交、PR 差异、测试，人工决定合并 | PR 真实存在且指向正确仓库/基线。PR 合并与项目验收分别核对；未合并不能宣称代码已入主分支 |
| X6 Issue 独立 | 若 B 关联 Issue，检查任务验收后 Issue 实际状态 | 当前没有验收后自动关闭 Issue 的实现；不能误报已关。此项记录现状，自动关闭作为后续能力，不判当前主链路失败 |

## 第 4 部分增量验收：自主跟进（2026-11-18）

已有重演项目可继续使用，不必再次清空或重建。完整设计、事件和默认配置见[自主跟进](events/autonomous-follow-up.zh-CN.md)。本节独立核验后台推进，不能把代码测试通过当作真实游戏交付。

- [ ] 项目 active、autoAdvance=true。A 交付只到待验收，B 不抢跑；人工通过 A 后，不发“开始 B”，观察 B 的 task.ready、Agent 工具结果和一条真实工单。重复刷新或重启不重复派发。
- [ ] 如 A 已验收、B 正在执行，不要为测试而伪造新的验收；直接验证 B 后续事件。
- [ ] B 报告实际阻塞，群里收到 Markdown 简短通知及真实 @。系统 Agent 记录包含 task.blocked；能用已有信息解决时补充原工单，需要人工时保留明确行动项，不假装群内同意能批准原生权限。
- [ ] 同一问题连续报告，不重复开启管理 Agent 轮次。没有新行动时允许安静；成功启动或跟进后必须给简短实际结果。
- [ ] 对机器人说“半小时后再看看这个任务，没有变化就不用提醒”。核对 follow_up.schedule 实际结果中的时间及原因，不接受只有口头承诺。
- [ ] 到点后无需 @：出现 check.due 和 Agent 处理记录。有动作就核对原工单和消息，没有新信息则不应刷屏。
- [ ] 替换或取消预约、暂停项目或关闭自动推进，旧检查不再执行。模型正在判断时暂停也不能落地旧操作。
- [ ] 未到期时重启，预约仍在；逾期重启会补入队一次。B 真正交付后仍请求人工验收，不自行完成 C、关闭 Issue 或合并 PR。

读取证据使用本机 API，请求头 X-Orchestrator-Request: 1：项目 events、agent-runs、checks 三个入口。真实群通知须以 Outbox sent 和客户端实际展示交叉确认。


## 9. 第 5、6 部分增量验收：GitHub 与推进记录

本节直接继续现有 A/B/C，不要求删除或重新创建真实项目。既有 B 关联保持默认“仅参考”；不要为了验收直接把 B 标记完成。

| 编号 | 人工操作 | 通过标准 |
| --- | --- | --- |
| G1 存量迁移 | 刷新项目，左栏进入“推进记录”，再重启一次服务 | 有一份存量基线；原项目、成员、任务、工单、验收历史保留；不重放历史验收，不因迁移关闭 Issue |
| G2 原因与结果 | 群里自然地请求查看 B 现状并预约两分钟后检查，明确先不修改或验收任务 | 记录能看到原消息、Agent 工具决定、实际工具结果；有真实到期事件；没有新事实可静默，不新增执行工单 |
| G3 多仓库与可选关联 | 独立测试项目分别不关联仓库、关联不同仓库；任务可不关联 Issue | 各项目事实不会串台；一个仓库读取失败不阻止其他仓库事实进入队列；无仓库任务正常执行报告交付 |
| G4 PR 交付 | 独立测试任务选择 PR 交付，指定真实 PR 与目标分支；执行者报告 ready，PR 尚未合并 | 不进入待验收；远端关闭但未合并仍不能交付。负责人审查合并后，报告与已合并证据齐备，只创建一次验收 |
| G5 版本证据 | 打开该版交付及推进记录 | 保存 PR URL、head、合并提交、目标分支、核验时间；旧版、其他仓库或错误目标分支不能替代 |
| G6 验收后关 Issue | 在独立测试仓库/任务上，明确选择“本任务负责解决”；先提交交付，再由负责人实际验收通过 | 工单 ready 与 PR 合并均不提前关闭 Issue；验收后出现关闭请求与远端成功回执；GitHub Issue 实际 closed，任务状态与同步状态分别展示 |
| G7 参考关联 | 另一任务关联 Issue，保持“仅参考”，人工验收通过 | 不产生关闭请求，不修改远端 Issue |
| G8 失败恢复 | 在测试环境模拟远端超时或权限失败后恢复权限，必要时在推进记录点击重新核对 | 临时失败保留待确认并自动读取远端后重试；权限失败显示原因，可显式重试；已成功的不重复关闭。运行中改变授权则取消尚未发送的动作 |
| G9 顺序与证据 | 展开事件证据，连续翻页，再刷新页面 | 能看到 seq、事件来源、causeId、Agent 决策与真实回执；相同时间的事件不漏页、不重复；任务筛选生效 |

**真实群验收记录方式：**记录群消息时间/ID、项目事件 seq、Agent run ID、预约与到期 ID、Outbox 回执及看板变化。自动测试模拟网络、真实只读 GitHub 核验和真实群验收分别记载。未经成员实际交付和验收，不为凑通过率关闭真实业务 Issue。

配置见 [PR 交付事件](events/repository.zh-CN.md)、[Issue 事实事件](events/repository.zh-CN.md)、[验收后关闭 Issue](events/repository.zh-CN.md)和[推进记录与存量迁移](events/project-history.zh-CN.md)。
